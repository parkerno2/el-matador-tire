# El Matador Tire / Matchweek: notes for Claude sessions

This repo runs Parker's 8-manager FPL Draft league app (El Matador Tire). The product name is **Matchweek**. **Rule zero:** everything runs without Parker's computer, so never add a step that needs it.

## Rules
- **Secrets:** never put a key, token or password in the repo, a prompt or a message. Keys live in Apps Script Script Properties (`ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`), which Parker sets himself.
- **Design:**
  - no emoji in the UI;
  - every number shown is real and traceable to data;
  - the voices are fictional (Malcolm Tyre, Archizio Poblano, Clark Moldridge, Jive Tidlsey);
  - the palette is purple and blue (app tokens);
  - no em or en dashes in generated text.
- **Tone** (Parker, 8 Oct 2026): funny means **clever, not rude**, aimed at eight early-20s lads on football Twitter.
  - Every joke rests on a real fact: irony, a team name or cliché turned back on itself, a precise football-Twitter parallel, or a deadpan undercut. Reference line: "Fully fit. Just shite."
  - Swearing is seasoning only.
  - Hard limits: nothing about anyone's real life (looks, family, partners, jobs, money, health); no slurs of any kind; nothing sexual.
  - See `fplgg/tools/matchweek/docs/TONE.md`.
- **Articles** (Parker, 8 Oct 2026: "i don't want to approve it just go for it"): recaps and previews publish automatically once they pass the checks. Parker, as commissioner (team Cold Palmers, `EMT_COMMISH`), fixes things afterwards from his phone: ask for a rewrite of a live article (the live version stays up until the new one passes) or take it down. Script Property `EMT_ART_REVIEW = yes` brings back approve-before-publish; respect it when it is set.
- **Testing before you push:**
  - App: test changes with `cd fplgg/tools/matchweek && npm ci && bash ci-build.sh`.
  - Code.gs: run `node tests/codegs/<file>.js` for v328, v327, v326, v325, v324, v323, v322, v321, v320, v319, v318, v317, v315, v314, v313, v312, show and test; all must print ALL PASS (test.js prints rows). The CI gate runs the same suites and only a passing commit reaches `release`, which the live script installs within the hour; a red run means the league keeps the previous Code.gs until main is fixed. The gate finds its suites by pattern (`tests/codegs/*.js` and `tests/*.js`, skipping `*harness*` and `*fixtures*`), so a new `tests/*.js` needs no registration anywhere; `tests/codegs/v315.js` checks that pattern, never a list of files.
  - App error reporting: `node tests/app-errors.js`. Sheet reader guard and stale banner: `node tests/app-tabs.js`. The data source behind the flag (`?data=supabase`, ROADMAP B3): `node tests/app-data.js`. The engine's provisional bonus (a double gameweek reads the `Fixture BPS` tab): `node tests/app-bonus.js`. The engine's fixture difficulty from the Clubs tab (Str H, Str A): `node tests/app-fdr.js`. Player images (an FPL photo is framed by the head, class `fpl` from the shared chain) and the small Plate (`UI.plateMini`, `UI.plateNum`): `node tests/app-faces.js`. The Lineup list view's club crests (the player's club and the opponent's, from the engine's `badgeImg`): `node tests/app-crests.js`. The Feed's Manager of the Month rules (`src/feed/curate.js`): `node tests/app-feed.js`. The Gameweek Show's audio contract (only current takes play) and caption clock: `node tests/app-show.js`. The demo league's data source, anonymiser and leak check (`src/data/tabs.js` with `__MW_DEMO__`, `fplgg/tools/demo/`): `node tests/app-demo.js`; the headless check of the built demo (`NODE_PATH=/opt/node22/lib/node_modules node fplgg/tools/demo/check-headless.js`) is not in the gate. An engine change goes in `src-prod/` (`base.js`, `v10.js`, `v12.js`) and `core.gen.js` alike (the extractor `tools/extract.js` drops standalone comments, so keep the two files in step by hand). Monitor: `node tests/monitor.js`. Supabase parity report: `node tests/parity.js`. matchweek.gg Worker: `node tests/worker.js`. The status page (its script run against a crafted `?health=1`): `node tests/status.js`. The CI gate runs all of these too.
  - Facts bot: `node tests/factsbot.js` (and `NODE_PATH=/opt/node22/lib/node_modules node fplgg/tools/factsbot/factsbot.js --out /tmp/facts` runs it for real against the live app).

## Pipelines (Code.gs v3.28)
- **`aiTick`, every 15 minutes:**
  1. `aiWriterTick`: feed posts on Haiku.
  2. `showWriterTick`: show script on Sonnet, with a Haiku punch-up; since v3.28 in dry British commentary (TONE.md, "The Gameweek Show"): the season's storylines and the league's running jokes, no joke built on a number, 6 to 18 words a beat, at most two subtle delivery tags a show and never whispering.
  3. `showTick`: ElevenLabs voice, on `eleven_v4_turbo` since v3.26 (`EMT_TTS_MODEL` wins; the script json's `model` is a label; a v4 model gets `voice_settings { stability, similarity_boost }` only; audio tags in square brackets go to ElevenLabs and never to a caption or the Words column; a 400 or 422 pins the gameweek to `eleven_multilingual_v2`, `EMT_SHOW_MODEL_GW_<gw>`, so hashes never flip). Since v3.25 the credits are guarded: a render reads the account's balance first (`GET /v1/user/subscription`; a key without `user_read` falls back to a count kept in Script Properties against `EMT_SHOW_MONTHLY_LIMIT`, default 10,000) and skips when the lines to voice would not fit; a script version voices at most its length plus a quarter (v3.27: counted per script version in `EMT_SHOW_GW_VER_<gw>`, so a hand-written rewrite gets its own allowance, at most 3 versions a gameweek with one of their own, later rewrites measured against the last; `EMT_SHOW_GW_CAP_<gw>` caps the gameweek as a whole when set); after a credit refusal nothing is rendered until the reported reset (`EMT_SHOW_HOLD`, 24 h when unknown), with an hourly balance read so a top-up is noticed, and the menu's Render now lifts the hold. Never weaken these.
  4. `articleTick`: recap and preview through the Message Batches API: research with web search, writing on Sonnet, then a Haiku punch-up. An article that passes the checks goes live at once (with `EMT_ART_REVIEW = yes` it waits as a draft for the commissioner).
  5. `selfUpdateTick` (from the `release` branch since v3.16).
- **Facts:** phones send them (`showfacts` for previews and the show, `artfacts` for recaps), computed by the app's own engine, so articles match the screen. Since v3.15 the Facts bot sends the same facts from the cloud (`facts` branch); Code.gs takes whichever is newer and checks a repo file exactly as a phone's post.
- **Health:** `GET <web app>?health=1` (`articles.mode` is `auto` or `review`; `show.credits`, `show.cap`, `show.capped` and `show.hold` are the ElevenLabs guard (v3.25); `ai.last` is the feed writer's last run (events due, posts made, any error), so a quiet day and a broken writer read differently; `facts` says where the newest preview and recap facts came from, phone or repo; `data` has `updated` (the last refresh from FPL that finished), `attempted`, `live` and `liveSince`; `errors` counts what phones reported in the last 24 h, from the hidden Errors tab). Without a browser, read the Articles, ShowScripts, RecapFacts and ShowFacts tabs over gviz, and `https://raw.githubusercontent.com/parkerno2/el-matador-tire/facts/facts/index.json`.
- **Model chains:** every writer has a fallback chain (`EMT_*_MODEL` Script Property first), so a retired model falls through by itself. The Claude 5.5 models think before answering and the thinking counts against `max_tokens`: `emtModelParams` (v3.20) turns it off for the quick synchronous calls (feed, show) the way each model allows, and the batch calls (articles) carry budgets with room for it: 32,000 tokens each for the research, the writing and the punch-up since v3.23 (8,000 and 16,000 ran out before the notes or the JSON, BUGS #28). Never lower those budgets back; the research line in an article's Log says when a budget ran out.
