# Run report, 10 Oct 2026: the Player of the Month month written as text (Code.gs v3.31, an outage fix)

## The request
Step 1 of the builder's run (18:59 UTC): "If something is broken and the cause is clear, fixing it is this run's item (an outage fix may go straight to main and may ship inside a live gameweek window)."

## What was seen
- 19:02 UTC: the Specials tab over gviz CSV without `headers=1` answered `"Setting POTM player","Value Groß"` as its header and `"API URL",""`; `out:json` showed column B typed `date`, `parsedNumHeaders: 2` and the API URL cell `null`. With `headers=1` the same tab answered its four rows whole, the URL included.
- `?health=1`: ok, v3.30 (self "updated to v3.30 v16 at 18:51"), `potm: { month: "Tue Sep 01 2026 00:00:00 GMT-0500 (Central Daylight Time)", player: "Groß", from: "hand" }`.
- The Monitor's run 185 (19:00 UTC, https://github.com/parkerno2/el-matador-tire/actions/runs/38078062924) failed its sheet check twice and opened outage issue #2, "the league sheet does not answer", at 19:04:39 UTC, assigned to Parker. Nothing was down: the app sends `headers=1` and read the tab correctly the whole time.

## Cause
Code.gs v3.30's `emtPotmSync` wrote the month with `setValue('September 2026')`, and Sheets parsed the string into a date (1 September 2026, format `mmmm yyyy`). With a date in the Value column, gviz's header guess took two rows as the header and served the string cell under them as null. The Monitor's Specials read did not send `headers=1`.

## What changed
- `Code.gs` v3.31: `emtPotmSetText` sets the plain-text number format (`@`) on a Value cell before writing it, and both writes go through it; `emtPotmMonthText` reads a Date as `<Month> <YYYY>`; the sync rewrites a date in the month cell as that text before comparing, so the live cell heals on the next hourly read without changing what it says (a hand edit for another month is healed too, then the file wins as in v3.30); `emtPotmHealth` reads a date cell as its text, so the sync's own write reads `file` again. Header line, CHANGELOG entry, `EMT_VERSION`.
- `fplgg/tools/monitor/monitor.js`: `SPECIALS_URL` carries `headers=1`, as the app's reader does.
- `tests/codegs/harness.js`: the range mock gains `setNumberFormat` (recorded per cell, in order) and `setValue` returns the range.
- `tests/codegs/v331.js` (18 checks): the version and the entry, every write through `emtPotmSetText`, the month text from strings and Dates, a new month written with the format set first on each cell, the API URL row untouched, a date cell healed and kept with its log line, the next hour quiet, a hand edit parsed into a date, health before and after, the Monitor's URL.
- `tests/monitor.js`: the Specials URL carries `headers=1`.
- `CLAUDE.md` (the test list, the Player of the Month paragraph), `tests/codegs/README.md`, `BUGS.md` (#42 closed, the audit line), `ROADMAP.md` (a sentence in the Q7 entry).
